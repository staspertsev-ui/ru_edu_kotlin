### 1. Регистрация и управление учетной записью:

1.1. **Регистрация на платформе:**

- **Источник требования:** Лечебные заведения, доктора, пациенты.
- **Описание требования:** Реализовать функционал регистрации с обязательными полями для заполнения и
  подтверждением через электронную почту.
- Поля для заполнения включают:
    - Электронная почта (обязательное поле)
    - Пароль (обязательное поле)
    - Тип пользователя (Доктор/Пациент)
    - Контактный телефон (обязательное поле)
    - Дата создания (заполняется автоматически при сохранении)
    - Фамилия (обязательное поле)
    - Имя (обязательное поле)
    - Отчество
- Поля для Пациентов
    - Врачи, которым будет доступна статистика МНО
    - Дата рождения пациента (обязательное поле)
    - Диагноз
    - Антикоагулянт (обязательное поле)
    - Мин. возможное значение МНО (обязательное поле)
    - Макс. возможное значение МНО (обязательное поле)
- Поля для Врачей
    - Специализация
- **Приоритет требования:** Высокий.

1.2. **Вход в систему:**

- **Источник требования:** Все типы пользователей.
- **Описание требования:** Обеспечить возможность аутентификации пользователей по электронной почте и паролю.
- **Приоритет требования:** Высокий.

### 2. Управление профилем пользователя:

2.1. **Профиль пользователя:**

- **Источник требования:** Все типы пользователей.
- **Описание требования:** Разработать возможность заполнения и редактирования профиля пользователя. Поля
- **Приоритет требования:** Средний.

- **Источник требования:** Пациент
- **Описание требования:** Разработать возможность изменения списка врачей, которым будет доступна статистика пациента
- **Приоритет требования:** Средний.

### 3. Управление справочниками антикоагулянтов

- **Источник требования:** Все типы пользователей.
- **Описание требования:** Разработать возможность получения справочника антикоагулянтов. Поля справочника:
    - Наименование антикоагулянта
    - Единица измерения
- **Приоритет требования:** Высокий.

- **Источник требования:** Все типы пользователей.
- **Описание требования:** Разработать ведения возможность получения справочника единиц измерения дозировки лекарств. Поля справочника:
    - Наименование единицы измерения
- **Приоритет требования:** Высокий.

- **Источник требования:** Все типы пользователей.
- **Описание требования:** Разработать возможность ведения справочника специализаций врачей. Поля справочника:
    - Наименование специализации
- **Приоритет требования:** Высокий.

### 4. Управление статистикой:

4.1. **Добавление измерений:**

- **Источник требования:** Пациент
- **Описание требования:** Разработать возможность сохранения следующих статистических данных:
    - Пациент (id)
    - Дата измерения
    - Уровень МНО
    - Доза антикоагулянта
    - Вид антикоагулянта
- **Приоритет требования:** Высокий.

4.2. **Просмотр статистики измерений:**

- **Источник требования:** Пациент
- **Описание требования:** Разработать возможность получения измерений за период по текущему пользователю (пациенту)
- **Приоритет требования:** Высокий.

4.2. **Просмотр статистики измерений:**

- **Источник требования:** Врач
- **Описание требования:** Разработать возможность получения измерений за период по указанному пациенту
- **Приоритет требования:** Высокий.

### 5. Управление рекомендациями:

- **Источник требования:** доктора
- **Описание требования:** Разработать возможность добавления (редактирования) рекомендация для пациентов со след палями:
    - Пациент (обязательное поле)
    - Создатель (заполняется автоматически при сохранении)
    - Дата создания (заполняется автоматически при сохранении)
    - Дата последнего изменения (заполняется автоматически при сохранении)
    - Текст рекомендации (обязательное поле)
- **Приоритет требования:** Средний.

- **Источник требования:** Пациент
- **Описание требования:** Разработать возможность просмотра рекомендаций для пациента 
- **Приоритет требования:** Средний.
